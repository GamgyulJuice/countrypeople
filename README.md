# 시골로 · countrypeople

귀농·귀촌 맞춤 정책 추천과 정착 준비 관리 MVP입니다. React + TypeScript + Vite, `@supabase/supabase-js`를 사용합니다. 정책 신청은 접수하지 않고 원문 출처로 안내합니다.

## 로컬 실행

Node 22 이상과 pnpm이 필요합니다.

```sh
pnpm install
pnpm dev
```

브라우저에서 `http://127.0.0.1:5173`을 엽니다. 공개 키와 URL을 모두 설정하지 않으면 데모 모드로 실행됩니다. 이 모드의 정책·조건·기간은 **가상 예시**이며 공식 사이트 링크는 정보 탐색용입니다. 데모 수정 사항은 현재 브라우저의 localStorage에만 저장되고 실제 DB로 자동 이전되지 않습니다. 실제 연결의 데이터 오류를 데모로 대체하지 않습니다.

### 첫 방문 조건 입력

Supabase 연결이나 회원가입 없이도 **3단계 조건 입력 폼**을 사용할 수 있습니다. 처음 방문하면 샘플 사용자 대시보드를 건너뛰지 않고 아래 순서로 진행합니다.

1. **이주 계획:** 이름, 생년월일, 귀농/귀촌/탐색 목적, 현재 지역, 희망 시도·시군구, 전입일 또는 시기 미정, 준비 단계, 희망 업종.
2. **준비 상황:** 직업, 도시 거주기간, 세대주, 소득구간, 영농 시작일·경영체·농지(귀농/탐색형), 교육 수료기록, 앱 내 알림. 교육은 **교육 추가**로 여러 과정을 등록하고 각 항목을 삭제할 수 있습니다. 교육별 이름·기관·시간·수료일·수료증 여부를 입력하면 수료시간이 합산됩니다. 선택 정보는 비워둘 수 있습니다.
3. **맞춤 계획 확인:** 정책별 조건 결과와 공식 출처, 자동 생성할 일정을 미리 보고 저장합니다. 이후 입력한 사용자 기준으로 대시보드가 열립니다.

목표 전입일, 귀농/귀촌 목적, 이미 전입했는지, 희망 업종과 부족한 교육시간이 초기 일정에 반영됩니다. 시기가 미정이면 오늘부터 탐색 일정이 생성되고 이미 지난 준비 시점은 앞으로 조정합니다. 교육 기록은 수료 정보가 있을 때만 저장합니다.

기존 사용자는 **내 조건 다시 입력하기** 또는 `http://127.0.0.1:5173/?onboarding=1`로 폼을 다시 열 수 있습니다. 저장된 프로필을 미리 채우고 기존 할 일·교육을 보존합니다. 같은 제목·날짜의 일정을 중복 추가하지 않습니다. 저장 완료 후 새로고침하면 다시 대시보드로 진입합니다.

Supabase 연결 시에도 같은 폼을 사용합니다. 기간형 일정 저장에는 아래의 두 번째 migration까지 적용해야 합니다. 초기 자식 기록을 upsert한 후 프로필을 마지막으로 저장합니다. 네트워크 중단 시 일부 자식 기록이 저장될 수 있지만 폼의 입력과 UUID를 유지하여 재시도할 때 중복 생성을 방지합니다. 다중 테이블의 원자적 트랜잭션이 필요한 운영 환경에서는 별도 DB 함수로 확장할 수 있습니다.

## Supabase 연결: 사용자가 Dashboard에서 직접 설정

개발 과정에서는 원격 Supabase 프로젝트 또는 DB에 접속하지 않았으며, MCP와 Supabase CLI를 사용하지 않습니다. `.env.local`은 생성·변경하지 않습니다.

1. Dashboard의 **SQL Editor**에서 새 프로젝트는 `supabase/migrations/202610030001_initial_schema.sql`, `supabase/migrations/202610030002_task_periods.sql`, `supabase/migrations/202610030003_education_roadmap.sql` 순서로 각각 한 번 실행합니다. 이미 적용한 migration은 제외하고 새 파일만 실행하세요. 세 번째 파일은 교육 일정과 수료 이력 자동 연동에 필요합니다. 초기 스키마를 다시 실행하거나 기존 테이블을 삭제하지 않습니다.
2. Dashboard에서 이메일/비밀번호 인증 설정을 확인하고, Authentication의 URL Configuration에서 사용하는 로컬 주소와 이메일 인증 리다이렉트 주소를 허용합니다. 이메일 확인이 켜져 있으면 가입 메일의 인증 링크 확인 후 로그인합니다.
3. `VITE_SUPABASE_URL`과 `VITE_SUPABASE_PUBLISHABLE_KEY`를 **셸 또는 배포 환경변수**에 설정합니다. 환경파일은 예제 파일을 포함해 Git 저장소에서 제외합니다. `VITE_` 값은 공개되는 브라우저 번들에 포함되므로 공개용 publishable key 또는 기존 anon key만 사용합니다. secret / service_role 키는 사용하지 않습니다.
4. 환경변수 변경 후 개발 서버를 재시작합니다. 공개 키가 설정되면 로그인 화면이 나오며, 첫 로그인에서는 프로필을 작성합니다.
5. 정책은 `supabase/policy-template.sql`을 참고하여 Dashboard에서 관리자가 직접 등록합니다. 개별 공식 원문 URL, 시행기관, 기준연도, 확인일, 조건을 검증한 다음 `is_published = true`로 공개합니다. 실제 DB에는 가상 정책을 자동으로 넣지 않습니다. 따라서 첫 연결 시 빈 정책 화면이 정상입니다.

Windows PowerShell 예시 (`.env.local` 생성 없이):

```powershell
$env:VITE_SUPABASE_URL = 'https://YOUR_PROJECT.supabase.co'
$env:VITE_SUPABASE_PUBLISHABLE_KEY = 'sb_publishable_YOUR_PUBLIC_KEY'
pnpm dev
```

원격 DB 연결 검증은 사용자가 위 설정을 마친 뒤 수행해야 합니다. 앱 사용 시에만 브라우저가 Supabase Auth와 REST API에 직접 요청합니다.

## 데이터 구조와 접근 제어

| 테이블 | 용도 | 접근 |
| --- | --- | --- |
| `profiles` | 기본 프로필·희망 시군·일정·추가 진단·알림 설정 | 본인 CRUD |
| `policies` | 정책 내용·공식 출처·기관·기간·기준연도·확인일 | 공개 정책 읽기 전용 |
| `policy_rules` | 정책별 필드·연산자·조건값·보완 안내 | 공개 정책의 규칙 읽기 전용 |
| `policy_documents` | 정책별 서류 체크리스트 정의 | 공개 정책의 서류 읽기 전용 |
| `saved_policies` | 관심 정책 | 본인 CRUD |
| `tasks` | 할 일·기한·완료·선택적 정책 연결 | 본인 CRUD |
| `education_records` | 교육 수료·기관·시간·수료증 보유 | 본인 CRUD |
| `document_checks` | 사용자별 준비서류 완료 상태 | 본인 CRUD |
| `weekly_checkins` | 주간 메모·완료 현황 스냅샷 | 본인 CRUD |

모든 테이블에 RLS를 활성화합니다. 개인 테이블은 `auth.uid() = user_id`의 SELECT/INSERT/UPDATE/DELETE 정책을 각각 가지며 소유자 변경도 거부합니다. 익명 역할에는 개인 테이블 권한이 없습니다. 정책 카탈로그는 클라이언트 쓰기 권한이 없고 비공개 정책과 하위 데이터도 노출하지 않습니다. FK, 중복 방지 키, 날짜·수치·규칙 타입 CHECK, 조회 인덱스 및 변경 시각 트리거를 포함합니다. Auth 사용자 삭제 시 개인 기록을 cascade 삭제합니다.

프로필은 Auth 가입 트리거 대신 최초 프로필 폼 저장 시 생성합니다. 가입 전송이 프로필 작성으로 오인되지 않도록 로그인 세션과 프로필 완료를 구분합니다. UI에는 계정 삭제 버튼이 없으며 관리자는 Auth Dashboard에서 삭제할 수 있습니다.

## 구현된 흐름

- 이메일 회원가입·로그인·로그아웃, 로그인/설정/조회 오류와 재시도
- 1차 프로필과 선택적 추가 진단, 귀농·귀촌에 따른 질문 분기
- 조건 기반 정책 추천, 조건별 통과/미충족/미입력 표시, 검색·분류·관심 정책
- 정책 출처·기준연도·확인일·기관·원문 링크·서류 체크리스트
- 목표일 기반 로드맵 생성, 할 일 등록·수정·삭제·완료, 준비도 계산
- 로드맵 목록/월별 캘린더 전환, 이전·다음 달/오늘 이동, 시작일 입력과 다음 할 일 전날까지 자동 계산되는 종료일, 기간을 가로지르는 막대와 겹치는 일정의 줄 분리. 날짜를 누르면 해당 날짜에 진행되는 모든 일정이 나오고, 막대를 누르면 수정할 수 있습니다. 주·월 경계와 모바일에서도 같은 기간을 표시합니다.
- 교육 수료 기록 CRUD와 교육시간 재계산, 미래 수료일 입력 제한
- 로드맵·교육 이력의 **교육 로드맵에 추가**로 교육명·기관·시간을 미리 등록합니다. 완료를 체크하면 실제 수료일(기본값: 한국 날짜 기준 오늘)과 이력이 자동 저장되고 대시보드·로드맵·교육 이력의 총 수료시간에 반영됩니다. 완료 취소 시 연결 기록이 제거되고, 다시 완료해도 같은 일정에 기록이 중복되지 않습니다.
- 교육 이력에서 자동 생성된 기록의 이름·기관·시간·수료일을 수정하면 원래 교육 일정도 함께 갱신됩니다. 기록 삭제는 연결 일정의 완료 취소로 반영됩니다. 완료된 교육 일정 자체를 삭제하면 연결된 수료 기록도 삭제되며 화면에서 안내합니다. 기존 직접 입력한 기록은 유지합니다.
- 로드맵 항목의 **준비서류 · 연락처 · 신청 사이트**를 펼치면 진행 순서, 서류 이름과 준비 방법, 문의처, 공식 링크를 확인합니다. 이전에 저장한 추상적인 제목도 해당 단계 안내를 사용할 수 있습니다. 공통 준비자료와 공고별 필수 제출서류를 구분하며 데모 정책의 가상 서류는 실제 의무로 안내하지 않습니다.
- 앱 내 일정 알림: 관심 정책의 30일 이내 마감과 진행 중·7일 이내 시작할 일(기한 경과 포함)
- 대시보드·주간 브리핑의 할 일은 로드맵 전체 구간 중 한국 날짜 기준 이번 주 월요일~일요일과 겹치는 동일한 항목입니다. 완료 항목도 표시하며 3개로 자르지 않습니다. 전체·완료·남은 개수를 공유하고, 어느 화면에서 수정·삭제·완료해도 함께 반영됩니다. 지난 주에 끝난 일정과 다음 주부터 시작하는 일정은 제외합니다.
- 이번 주 체크인 저장/수정·과거 기록. 저장 시점의 동일 주간 집계를 기록하며 주차가 바뀌면 메모도 해당 주차로 전환합니다.
- 데스크톱/모바일 반응형 UI, 모달 키보드 포커스 및 Escape 닫기

## MVP의 범위와 후속 확장

- 이메일 뉴스레터·문자·푸시·백그라운드 발송은 아직 구현하지 않았습니다. 주간 브리핑과 알림은 앱 내부에서 확인합니다.
- 추천은 **자격 판정이나 선정 확률이 아닙니다**. 규칙은 AND 결합의 숫자 `gte/lte/eq`와 문자열/불리언 `eq`만 지원합니다. 규칙이 없거나 정보가 누락되면 추가 확인으로 표시합니다. 복합 예외, 정책별 연령 기준일·소득 심사, 교육 인정 기관·기간·상한 등은 시행기관 확인이 필요합니다.
- 시·군까지 입력받으며 정책 `region`은 `전국` 또는 `전라남도 담양군` 같은 동일한 정규 표기를 사용합니다. 행정구역 코드 데이터셋은 아직 포함하지 않았습니다.
- 현재 준비도는 등록된 할 일 완료율입니다. 로드맵 생성은 같은 제목·날짜 중복을 피하지만 목표일 변경 시 기존 할 일을 자동 이동하지 않습니다.
- 정책 자동 수집, 공식 공고 검증 자동화, 지역 가격 비교, 주소 이력 계산, 첨부 서류 업로드, 상세 금융/가족 정보는 후속 범위입니다. 수집하지 않는 민감정보는 DB에도 임의 추가하지 않았습니다.
- 실제 정책을 공개할 때 출처·날짜·조건·개인정보 안내를 점검해야 합니다. 지금 포함된 예시를 실제 정책으로 공개하지 마세요.
- 교육의 자동 기록은 **앱에서 사용자가 수료 완료를 확인한 이후** 동작합니다. 외부 교육기관의 학습 이력·진도·수료 여부를 조회하는 연동은 없습니다. 교육 탐색이나 신청 단계, 예정 시간은 실제 수료시간에 합산하지 않습니다. 수료시간은 학습 이력의 총합이며 사업별 인정 시간과 다를 수 있습니다.

### 교육 연동과 저장

- `tasks.education_provider`, `education_hours`, `education_completed_date`, `education_certificate`는 실제 수강 과정에만 설정합니다. 교육 분류만 있거나 '교육 알아보기'를 완료한 경우 수료 기록을 만들지 않습니다. 수료일은 로드맵의 표시 기간과 별도로 보존합니다.
- `education_records.task_id`가 있는 기록은 로드맵에서 자동 생성됩니다. 없는 기록은 기존 수동 입력입니다. DB에서는 일정별 유일한 연결과 동일 사용자 FK, 기존 RLS, `SECURITY INVOKER` 트리거로 일정 완료와 수료 기록을 한 트랜잭션에서 반영합니다. 데모도 동일한 동작을 localStorage에 저장합니다.
- 세 번째 SQL은 이 저장 구조를 추가하며 기존 기록을 임의 연결하거나 추정 수료시간을 생성하지 않습니다. 원격 DB에는 실행하지 않았습니다. 데모는 SQL 없이 사용할 수 있지만, 실제 연결에서는 앱 사용 전 새 migration을 적용해야 합니다.

### 기간형 일정과 기존 데이터

- `tasks.start_date`는 시작일, 기존 `due_date`는 종료일(마감일)입니다. 양 끝 날짜를 포함하며 시작일=종료일이면 하루 일정입니다. UI·저장 로직·DB CHECK에서 역전된 기간을 거부합니다.
- 기존 하루 일정도 바로 준비 구간으로 표시합니다. 시작일 누락/NULL은 기존 날짜를 시작일로 사용하고, 전체 일정에서 다음으로 늦은 시작일의 전날까지 이어집니다. 같은 날 시작하는 항목은 같은 다음 날짜를 기준으로 계산하며 마지막 항목은 저장된 종료일을 유지합니다. 이 표시 변경에는 추가 SQL이 필요 없습니다.
- 새 자동 로드맵은 전입일 기준 단계별 시작일을 제안하며 고정 30일/60일 기간을 사용하지 않습니다. **표시 구간은 다음 단계까지의 준비 구간이지 공식 공고나 수료 기간이 아닙니다.** 첫 입력 시 이미 지난 시작일은 오늘 이후로 조정합니다.
- 목록·캘린더·브리핑·알림은 동일하게 계산된 구간을 사용합니다. 추가·삭제·시작일 수정 시 자동 재계산하며, 완료 상태 필터는 계산 후 적용하므로 필터에 따라 길이가 바뀌지 않습니다. 완료 처리만으로 원래 날짜를 덮어쓰지 않습니다. 중간 항목의 종료일 입력은 읽기 전용이고 마지막 항목만 직접 지정합니다. 기존 주간 기록의 저장 시점 통계는 유지합니다.
- 두 번째 SQL은 기존 RLS·권한·관계를 유지합니다. 원격 DB에 실행하지 않았으며, 실제 연결에서 기간을 저장하려면 사용자가 먼저 SQL을 적용해야 합니다. 데모에서는 SQL 없이 바로 사용할 수 있습니다.

```sh
pnpm test
pnpm build

pnpm exec node scripts/smoke.mjs
# 첫 입력·재입력·저장 실패 재시도·귀촌 분기 전용 검증
pnpm exec node scripts/onboarding-smoke.mjs
# 여러 교육 입력·중간 삭제·시간 합산·추천 반영·저장 유지 검증
pnpm exec node scripts/education-smoke.mjs
# 교육 일정 완료/취소·수료 이력 양방향 수정·중복 방지·로드맵 상세 안내 검증
pnpm exec node scripts/education-roadmap-smoke.mjs
# 캘린더 월 이동·날짜별 CRUD·목록 동기화·모바일 검증
pnpm exec node scripts/calendar-smoke.mjs
# 다음 단계까지의 구간, 기존 하루 일정 변환, 추가·삭제·필터·새로고침 검증
pnpm exec node scripts/next-roadmap-smoke.mjs
# 대시보드·로드맵·주간 브리핑 양방향 완료/수정/삭제·집계 동기화
pnpm exec node scripts/weekly-sync-smoke.mjs
```

`tests/migration.test.ts`는 메모리 내 PostgreSQL(PGlite)에 Supabase Auth의 최소 계약을 구성한 다음 **실제 migration SQL**을 실행합니다. RLS, 사용자 위조, 타인 CRUD, 비공개 정책, 카탈로그 변조, 제약 및 cascade를 검증하며 원격 DB를 사용하지 않습니다. 실제 Supabase/PostgREST 연동 검증을 대체하지는 않습니다.

브라우저 검증은 새 임시 Edge 컨텍스트에서 데모만 실행하고 외부 네트워크 요청을 모두 차단합니다. 작업·교육 CRUD, 새로고침 유지, 정책 검색/빈 상태, 출처, 체크리스트, 저장, 프로필, 체크인, 모바일 오버플로와 런타임 오류를 확인합니다. 스크린샷은 Git에서 제외한 `artifacts/`에 생성됩니다.
